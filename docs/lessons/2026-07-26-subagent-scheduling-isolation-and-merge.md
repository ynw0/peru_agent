# 子 Agent 调度、隔离和合并经验

## 根因 1：并发槽和取消句柄登记过晚

任务从队列取出后，如果先异步创建工作区，再登记并发槽或 `AbortController`，父会话取消可能落入无句柄窗口，并发上限也可能被突破。修复为选中任务时原子占用槽位并登记取消控制器。

## 根因 2：尚未 start 的 queued 任务也属于父会话

只取消调度队列和运行任务，会遗漏“已 dispatch、尚未 start”的任务。父会话取消必须把所有 queued 记录明确转为 aborted，不能只返回成功计数。

## 根因 3：Reviewer 不能重新读取父工作区

Reviewer 或 Tester 如果从父工作区创建副本，看到的不是 Implementer 的实际结果。审核任务必须基于 Implementer 隔离工作区的精确快照。

## 根因 4：过滤模型可见 Tool 不足以形成权限边界

模型可能生成未展示或动态 Capability 更高的 ToolCall。能力策略必须同时应用于模型 Tool 列表、静态 Manifest、执行阶段和 `inspect()` 动态能力。

## 根因 5：子 Agent 完成不等于可以合并

Implementer 输出必须先通过 Reviewer 和 Tester，然后生成父工作区 Diff Proposal。只有用户接受 Diff 后，任务才能标记 merged。

## 根因 6：Patch 必须绑定隔离开始时的父文件哈希

子任务运行期间用户可能修改父工作区。生成 Proposal 前必须比较父工作区当前 SHA-256 与隔离基线，任一变化都停止合并。

## 根因 7：恢复校验不能拒绝所有不完整中间状态

进程可能在写入 running 状态和工作树快照之间崩溃。反序列化层若直接拒绝该记录，恢复器无法把它明确标记失败。持久化校验必须严格，但允许可识别、可安全收敛的崩溃窗口状态。

## 根因 8：清理后不能持久化失效 Worktree 引用

只读角色执行完会删除隔离目录。如果任务记录仍保存 Worktree，重启恢复会尝试加载不存在的目录。清理和持久化状态必须一致。

## 根因 9：快照隔离必须设置容量和根路径约束

没有文件数、总字节数和根目录绑定，隔离复制可能造成资源耗尽，持久化路径也可能被替换到任意目录。工作树必须限制容量并验证确定性路径。
