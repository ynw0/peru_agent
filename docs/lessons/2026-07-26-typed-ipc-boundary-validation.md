# Typed IPC 边界必须执行运行时校验

## 现象

最初的 Typed IPC 使用 TypeScript 泛型约束请求和响应，但 Client 在收到响应后直接把 `unknown` 强制转换成声明的结果类型；请求超时后也没有移除对应的 Abort 监听器。

## 根因

- TypeScript 类型只在编译期存在，跨进程消息在运行时仍是不可信数据；
- Pending Request 只保存回调，没有保存请求方法，导致无法按方法校验响应；
- 超时分支只删除 Map 项，没有执行统一资源清理。

## 修复方式

- 为每个 IPC 方法增加参数和结果运行时校验；
- Pending Request 保存原请求方法；
- Client 和 Server 同时验证响应结果；
- 超时、中止、正常响应和 Client 关闭都执行监听器清理。

## 新增测试

- 未知 IPC 方法拒绝；
- 未注册 Handler 返回稳定错误码；
- 请求超时；
- AbortSignal 主动取消；
- 正常初始化请求往返。

## 可复用规则

跨进程、网络、文件和插件边界的 `unknown` 数据不得仅靠 TypeScript 类型断言；必须执行运行时校验，并确保成功、失败、超时和中止路径释放相同资源。
