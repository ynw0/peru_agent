# Computer Use 身份和动作证据经验

## 1. 可执行文件名不是应用身份

### 根因

攻击者可以在其他目录放置同名程序，或者替换原程序内容。如果只检查 `editor.exe`，同名伪装程序会获得桌面交互能力。

### 规则

认证应用必须同时绑定安装路径、Publisher、Signer Thumbprint、精确文件 SHA-256、版本和窗口 Class。任一不匹配只能检查，不能交互。

## 2. HWND 也不是永久身份

### 根因

窗口关闭后 Handle 可能被系统复用；用户也可能在权限审核期间切换窗口或启动新进程。

### 规则

动作准备、动作执行和动作后验证都必须重新绑定 HWND、PID 和完整可执行身份。不得只缓存窗口标题或 Handle。

## 3. UI 元素序号不能作为动作证据

### 根因

窗口刷新、列表排序或异步渲染会改变“第 N 个元素”。仅保存元素索引可能点击到完全不同的控件。

### 规则

元素动作必须绑定 Snapshot、Runtime ID、Role、Name、Automation ID、Class 和 Bounds，并在动作前重新验证。

## 4. 未认证应用的读取能力不能自动升级

### 根因

“已经能看到 UI Tree”不代表“可以安全点击”。如果检查接口同时暴露动作执行，Workbench 或其他调用方可以绕过权限中心。

### 规则

IPC 仅开放检查、截图和审计。点击、输入和快捷键只能作为 `computer.interact` Agent Tool，经 PermissionCoordinator 审核后执行。

## 5. 输入明文不能进入事件或审计

### 根因

Computer Type 可能包含代码、文档内容或其他敏感文本。若将明文写入 Tool 卡片、事件日志或持久化动作，会扩大泄露面。

### 规则

准备动作只持久化文本 SHA-256；明文只保存在 Runtime 内存中，并在拒绝、过期、失败和完成路径清理。

## 6. 动作成功返回不等于动作安全完成

### 根因

应用可能在动作期间退出、重启、切换窗口或进入高完整性/敏感界面。只依据 API 调用成功会接受错误状态。

### 规则

Broker 必须在动作后重新获取 Snapshot，Runtime 必须再次认证应用身份。没有动作后证据时结果一律拒绝。

## 7. 数值边界也属于跨进程安全

### 根因

`Number(value)` 会把无效输入转换为 `NaN`，而 `NaN` 可能绕过普通比较。负尺寸和无穷坐标也会污染点击证据。

### 规则

所有坐标必须是有限数字，Width 和 Height 必须非负。跨进程 Snapshot 读取后必须运行时校验，不能依赖 TypeScript 类型断言。

## 8. 同步准备方法不能发射未处理异步事件

### 根因

同步动作准备中使用 `void asyncEmit()` 会留下无法被调用者观察的拒绝 Promise，可能产生未处理异常。

### 规则

同步 Runtime 的监听器必须是同步边界；需要异步副作用时应由上层显式调度和处理错误，不得 fire-and-forget。

## 9. 历史阶段契约不能固定当前协议版本

### 根因

Phase 9 网络源码审计把 `IPC_PROTOCOL_VERSION = 5` 写成精确文本。Phase 10 合法升级到 Version 6 后，网络能力本身没有退化，但旧审计错误失败。

### 规则

历史阶段依赖协议最低能力时必须验证 `version >= requiredVersion` 和所需方法仍存在，禁止把后续合法升级当作回归。只有协议要求精确相等的进程握手才使用严格版本匹配。
